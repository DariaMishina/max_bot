# План: Android-приложение «Сфера Таро» (только RuStore)

Отдельное приложение для Android на базе логики чат-бота в Max. Бот **не ломаем** и **не связываем** с приложением в первой версии.

Приложение — не окно в Max и не сайт в браузере, а обычная программа с иконкой на телефоне. Ставят из **RuStore**.

---

## Зафиксированные решения

| Вопрос | Решение |
|--------|---------|
| Отображаемое название и название в RuStore | **Сфера Таро** |
| `applicationId` / package name | **`ru.tarotsphere.app`** |
| Платформа | Только Android |
| Язык приложения | Kotlin + Jetpack Compose |
| Магазин | Только **RuStore** (Google Play — не делаем) |
| Оплата в приложении | Две опции на экране оплаты: **RuStore Pay SDK** и **ЮKassa** |
| База данных | **Отдельная** PostgreSQL, не таблица бота |
| Регистрация | **В первой версии нет.** Только гость. Входы — отдельным этапом позже |
| Входы позже (не MVP) | **VK ID**, **Яндекс ID**, **почта** — привязка к уже существующему гостю |
| Связка с аккаунтом бота Max | **Не делаем** (бэклог) |
| iOS / Flutter | Не делаем |
| HTTPS для API приложения | **[xTunnel](https://xtunnel.ru/)** — свой домен **не покупаем**. Пользователи URL **не видят** |
| Cloudflare | Только для **WebApp** бота (порт 8081). Для Android **не обязателен** |

Бот в Max живёт как сейчас: свои пользователи, свой баланс, своя ЮKassa. Покупка в боте **не** появится в приложении, и наоборот. Это ожидаемо, пока нет связки.

## 2. Как это устроено

```
  Бот Max                    Приложение Android
  (как сейчас)               (Kotlin, иконка на телефоне)
       │                              │
       ▼                              ▼
  БД бота                      БД приложения
  max_bot_db                   app_bot_db   ← новая, отдельная
       │                              │
       │                         Backend API
       │                      (HTTPS, свой процесс)
       │                              │
       └──────── DeepSeek, картинки карт ────────┘
                 (общий смысл логики, разные данные)
```

Код толкования (промпты, колода, пакеты) лучше **переиспользовать** из Python-сервиса, чтобы тексты раскладов не разъехались. Данные — **разные базы**.

Клиент на телефоне **никогда** не ходит в DeepSeek, ЮKassa API и PostgreSQL сам. Только в наш HTTPS API.

### 2.1. Стек приложения

- Kotlin, Jetpack Compose
- Навигация: Navigation Compose
- Сеть: Retrofit + OkHttp
- Состояние: ViewModel + Flow
- Кэш на телефоне: Room (история, баланс)
- Картинки карт: Coil, файлы из `static/` или с сервера
- Пуши: **RuStore Push** (на части телефонов нет сервисов Google, FCM может не работать)

### 2.2. Репозитории и CI/CD

Детали — §13. Коротко: бэкенд приложения в `max_bot`, Android в отдельном репо; бот можно не трогать.

Зафиксированное имя пакета: **`ru.tarotsphere.app`**.

### 2.3. Кто такой «пользователь» без регистрации

В Max id даёт мессенджер. В приложении его нет.

При **первом запуске** сервер создаёт гостя и отдаёт приложению токен. Приложение запоминает его на телефоне. Экрана входа **нет**.

| Когда | Что происходит |
|-------|----------------|
| Первая версия | Только гость. Гадает и покупает на этом устройстве |
| Удалил приложение / сменил телефон | Новый гость. Покупки и история **пропали** — так, пока нет входов |
| Позже (этап входов) | В профиле: «Войти через VK / Яндекс / почту». Вход **привязывается к текущему гостю**, баланс не обнуляется |
| Вошёл на новом телефоне | Тот же аккаунт (VK, Яндекс или почта) |

Порядок такой: сначала выпускаем приложение без регистрации, потом добавляем три входа. Не делаем забор «войдите, чтобы гадать».

## 3. API приложения

Префикс API: `https://01a0ba9c-b091-79dc-9a97-07e3b1eba847.tunnel4.com/v1/`. В `APP_API_PUBLIC_URL` серверного `.env` и `BuildConfig.API_BASE_URL` Android задаётся адрес без `/v1`; пути методов добавляет клиент.

Отдельный процесс, например `app_api_server.py`, порт не 8081 (у бота webhook). Не смешивать с `bot.py`.

Гостевой токен обязателен для запросов к данным пользователя. Исключения: создание/обновление сессии, `/health`, `/v1/docs` и изображения `/static/`. Это не «логин с паролем», а метка «этот телефон».

**Статус API на 2026-09-20:** методы экранов MVP развёрнуты на сервере и доступны через постоянный xTunnel. После применения `004_mvp.sql` и перезапуска `app-api` пройден живой сценарий гость → баланс → расклад DeepSeek → история. Входы, пуши, Ицзин, карта дня и платёжные методы ниже остаются планом следующих этапов.

### 3.1. Сессия

**Первая версия — только гость:**

| Метод | Путь | Зачем |
|-------|------|--------|
| POST | `/auth/guest` | Первый запуск: создать гостя, выдать токен |
| POST | `/auth/refresh` | Обновить токен |
| POST | `/auth/push-token` | Токен RuStore Push — ещё не реализован, этап 6 |

**Позже — входы (не в MVP).** Гостя не удаляем, а привязываем к нему способ входа:

| Метод | Путь | Зачем |
|-------|------|--------|
| POST | `/auth/vk` | Войти / привязать VK ID |
| POST | `/auth/yandex` | Войти / привязать Яндекс ID |
| POST | `/auth/email/start` | Код или ссылка на почту |
| POST | `/auth/email/confirm` | Подтвердить почту, привязать к гостю или войти |
| POST | `/auth/logout` | Выйти (гость на этом телефоне можно создать заново) |

Правило: если человек уже гость и нажимает «Войти через VK» — это **тот же** `user_id`, не новый аккаунт с нулевым балансом. Если VK уже занят другим пользователем — показать ошибку, не сливать балансы молча.

БД разная, поэтому **не** вызывать `main/database.py` бота из API приложения — иначе легко записать не туда.

## 4. Отдельная база приложения

Новая база `app_bot_db` на том же сервере PostgreSQL, что и бот. Бот к ней **не подключается**.

### Почему не «миграция»

| | `init_db.sql` (бот) | `init_app_db.sql` (приложение) |
|--|---------------------|--------------------------------|
| База | `max_bot_db` | `app_bot_db` |

| Смысл слова «миграция» | Со временем в файл добавляли ALTER | Просто **первичное создание** таблиц |

Для приложения это **инициализация новой БД**, не изменение `max_bot_db`.

## 14. HTTPS для API: xTunnel (без своего домена)

### Зачем это вообще

Приложение на телефоне **звонит на ваш сервер** по адресу `https://...`. Нужны:

1. **HTTPS** — иначе Android и оплата не работают нормально.
2. **Один и тот же адрес** — не меняется после перезапуска (для APK и webhook ЮKassa).

**Красивый домен пользователям не нужен** — URL вшит в код, в интерфейсе не показывается.

### Cloudflare — отдельная история

| | WebApp бота (браузер) | Android-приложение |
|--|----------------------|-------------------|
| Сейчас | Quick tunnel Cloudflare → порт **8081** | **Не используем** |
| Нужен Cloudflare? | Можно оставить как есть | **Нет** |

К Cloudflare **не привязаны**. Для приложения — **xTunnel**.

### Купленная лицензия xTunnel

19 сентября приобретена **Личная лицензия на месяц за 150 ₽**. Это цена покупки в кабинете пользователя; срок действия по кабинету — **до 19.10.2026**. Регистрация клиента на сервере подтвердила тариф **Personal**.

Свой домен у регистратора **не покупаем**: используется постоянный адрес xTunnel (`*.tunnel4.com`). Перед окончанием оплаченного периода нужно продлить лицензию для дальнейшей работы туннеля.

### Схема на VM

```
Android  →  https://....tunnel4.com/v1/...
                ↓
           xTunnel (на VM)
                ↓
      http://127.0.0.1:8083  ← app_api_server.py
                ↓
           app_bot_db
```

Порт **8083** — API приложения (`APP_API_PORT`). Порт **8081** — webhook бота / WebApp. Порт **8080** — psy_max.
