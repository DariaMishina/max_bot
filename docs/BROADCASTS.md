# Рассылки и автоматические напоминания

Все job'ы регистрируются в `bot.py` через APScheduler (timezone `Europe/Moscow`).

Чтобы отключить массовую рассылку карты дня, задайте в `.env`:

```bash
ENABLE_DAILY_TIP=false
```

При этом только карта дня не регистрируется в планировщике. Персональные
напоминания, обработка входящих сообщений и сверка платежей продолжают
работать. После изменения переменной перезапустите сервис бота.

Тексты отправляются из `send_message.py`. Для B/C2/C3/C4/expired доступна
LLM-персонализация по последним вопросам из раскладов; флаг
`PERSONALIZED_BROADCASTS=false` оставляет статичные fallback-шаблоны.

## Деплой / схема БД

Колонки рассылок создаются идемпотентными `ensure_*_columns()` в
`main/database.py`; актуальная схема новой установки также описана в
`init_db.sql`. Для описанного ниже C skip-ahead новая колонка и отдельная
миграция не нужны: используются существующие `free_nudge_*_sent_at`.

## Event-driven nudges

### Триггер A — истёк платный доступ

Серия day0–day7 после истечения unlimited или исчерпания paid-пакета.

- **day0** — сразу после истечения (без слота, grace period)
- **day1–day7** — слот по моменту истечения (`expiry_at`)

### Триггер B — платник давно не гадал

Условие: активный доступ, есть гадания, нет открытого платежа.

| Этап | Молчание |
|------|----------|
| 12h | 12 часов |
| 1d | 1 день |
| 48h | 2 дня |
| 3d | 3 дня |
| 5d | 5 дней |
| 10d | 10 дней |

Отправка в персональный слот 10:00–20:00 MSK (по `last_active_at`).

**Skip-ahead:** за цикл молчания — не более одного nudge; отправляется **старший**
из просроченных этапов (при тишине 25ч сразу `1d`, без предварительного `12h`).
Новое гадание сбрасывает все флаги и начинает цикл заново.

За один тик — максимум один этап на пользователя (B).

Функция: `send_paid_inactivity_nudge()`. Клавиатура: главное меню (`make_main_menu`) — без кнопок оплаты.

### Триггер C — бесплатные пользователи

Отправка без слота, проверка каждые 2 мин.

**C1** — не сделал ни одного расклада (якорь: `created_at`): +1ч / +3ч / +12ч / +24ч / +48ч

- к сообщению прикладывается кнопка «Новый расклад 🃏» (`make_divination_nudge_kb`)

**C2** — гадал, остались бесплатные (якорь: `last_active_at`): +3ч / +12ч / +24ч / +48ч

- к сообщению прикладывается кнопка «Новый расклад 🃏» (`make_divination_nudge_kb`) — без оплаты и без полного меню

**C3** — исчерпал бесплатные, не платил (якорь: `paywall_reached_at`): +1ч / +3ч / +12ч / +24ч / +48ч

- paywall: текст + `make_payment_kb()`

**C4** — есть бесплатные, молчит давно (якорь: `last_active_at`): +3d / +7d

- к сообщению прикладывается кнопка «Новый расклад 🃏» (`make_divination_nudge_kb`)

При новом гадании сбрасываются таймеры B, C2, C4 (`update_user_activity_on_divination`).

Для C1–C4 действует **skip-ahead**: выборка сразу определяет самый старший
просроченный этап категории. После успешной отправки выбранного этапа все
младшие этапы атомарно отмечаются пройденными. Поэтому накопившиеся во время
платёжного funnel этапы не отправляются затем каждые две минуты.

Между C-nudges разных категорий действует cooldown 1 час. Это важно для
пересекающихся C2 и C4: один пользователь не получит оба сообщения в одном
тике или на соседних двухминутных тиках.

Для B/C действует payment-funnel TTL 48ч:

- B блокирует только свежий `pending`; `canceled` не глушит активного платника;
- C1–C4 блокируют свежие `pending`/`canceled`, пока идут payment reminders;
- незавершённая серия payment reminders имеет приоритет над C1–C4;
- после любого payment reminder C1–C4 выдерживают cooldown 12 часов;
- за один цикл C отправляется только старший просроченный этап, младшие
  закрываются без отправки.

## Payment reminders

Этапы после `created_at` pending/canceled платежа:
10м, 1ч, 3ч, 12ч, 24ч, 48ч. При активном платном доступе не отправляются.

Payment reminders имеют приоритет над бесплатными C-nudges. Пока у попытки
оплаты не отмечен этап `48h`, C-nudge не выбирается; после последнего
payment reminder действует дополнительный cooldown 12 часов.

### Исправление catch-up от 20.10.2026

До исправления защита C1–C4 жила только в памяти одного запуска job. Если
несколько этапов становились просроченными, пока пользователя блокировал
payment funnel, после его завершения бот отправлял первый этап и на каждом
следующем двухминутном тике переходил к очередному. В подтверждённом случае
это дало `C2/12h`, `C2/24h`, `C2/48h` в 21:25, 21:27 и 21:29; одновременно с
первым сообщением пришёл payment reminder `48h`.

Теперь защита хранится в БД: выбирается старший due-этап, а его младшие флаги
закрываются тем же `UPDATE`. Незавершённые payment reminders и описанные выше
cooldown-фильтры исключают пересечение двух потоков.

## Персонализация

С флагом `PERSONALIZED_BROADCASTS=true` для B/C2/C3/C4/expired DeepSeek
получает до трёх последних типов и вопросов раскладов. Тексты проходят
ограничения длины/формата; при пустом контексте, ошибке API или невалидном
ответе отправляется статичный шаблон. C1 и payment reminders не персонализируются.

## Слоты (broadcast_schedule.py)

Окно 10:00–20:00 MSK, тик 30 мин. Слот = время `anchor_at` (или hash по user_id).
