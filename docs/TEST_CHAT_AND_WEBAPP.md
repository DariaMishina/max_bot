# Проверка чата и WebApp в тестовом MAX-боте

Работа ведётся в `max_bot`, ветка `feature/max-webapp`, база `max_webapp_test`. Продовый бот и его WebApp не переключаются на тестовую реализацию.

## Три сценария в одном боте

| Начало | Выбор карт | Ответ и уточнения |
|---|---|---|
| Вопрос в чате | Случайные карты либо названия своих карт в чате | В чате |
| Вопрос в чате | «Выбрать карты самой» открывает приложение; в нём «Выбрать карты для чата» | В чате, как у действующего выбора карт в продовом боте |
| Главная нового WebApp | Любой способ выбора и любая схема | В WebApp |

Это одно приложение с отдельным сценарием выбора карт для чата. Вопрос из чата показывается явно, но не подставляется в самостоятельный черновик WebApp. Обычное открытие приложения сохраняет чатовый диалог.

Баланс, записи истории и счётчик уточнений общие. Повторное открытие результата не создаёт новое гадание. Самостоятельные расклады WebApp не заменяют указатель чатового разговора. Для выбора карт под чат сервер проверяет пользователя, вопрос и версию начатого выбора; устаревшая вкладка отклоняется без списания.

## Запуск

Сохранить текущий cloudflared-туннель. В терминале тестового бота остановить процесс через Ctrl+C и запустить:

```bash
.venv-webapp/bin/python scripts/webapp_local.py max
```

База и туннель уже работают — перезапускать их ради изменения кода не требуется. Закрыть и заново открыть WebApp.

## Прогон с двух телефонов

Сначала использовать два разных тестовых MAX-аккаунта: проверить изоляцию вопросов, истории и балансов. Для проверки одновременных действий одного пользователя нужен один аккаунт, открытый на двух устройствах; два разных аккаунта этот случай не воспроизводят.

1. **Чат полностью.** Новый вопрос → Таро → «Карты покажут сами». Ожидается одна общая картинка трёх карт и ответ в чате. Написать уточнение — оно относится к этому раскладу. Повторить с «Написать свои карты» и отдельно с Ицзин.
2. **Привычный выбор карт в приложении.** Новый вопрос в чате → Таро → «Выбрать карты самой». В приложении выбрать «Выбрать карты для чата», затем три карты и «Получить ответ в чате». Приложение показывает завершение и кнопку возврата; ответ приходит в чат. Уточнение написать там же.
3. **Самостоятельный WebApp.** Открыть через меню, создать другой вопрос и пройти все три схемы и способы выбора. Ответ и уточнения появляются в приложении, без сообщений в чат. История показывает сохранённый результат.
4. **Переключение интерфейсов.** Получить чатовый расклад A. Создать в WebApp расклад B. Написать уточнение в чат: оно относится к A. Уточнение внутри B относится к B.
5. **Сохранение шага чата.** Начать ввод своего вопроса/карт в чате, открыть приложение и вернуться. Продолжение чата не должно потеряться.
6. **Устаревший выбор.** Открыть выбор карт для вопроса A. На втором устройстве начать в чате вопрос B. Отправить старый выбор A: отказ без списания, предложение открыть выбор заново.
7. **Повторные действия.** Повторить нажатие отправки и закрыть/открыть приложение во время ожидания. Один запрос должен дать одну запись истории и одно списание. Проверить повторное открытие готового ответа — баланс не меняется.
8. **Сбой и перезапуск.** Во время ожидания перезапустить только тестового бота. Запрос должен завершиться после запуска; повторное нажатие не создаёт второй расклад. При ошибке генерации списания нет.
9. **Остальные разделы.** Карта дня, история, избранное, заметки, баланс, базовая и подробная консультации. Оплата проверяется только после подключения тестового магазина ЮKassa; текущая заглушка оплаты не является проверкой платежа.

Для каждого пункта записать аккаунт, устройство, время, ожидаемый/фактический результат и изменение баланса. Физический прогон в MAX не заменяется автоматическими тестами.

## Автоматические проверки

```bash
.venv-webapp/bin/python scripts/test_webapp.py
.venv-webapp/bin/python scripts/test_webapp_ui_regressions.py
```

Серверные проверки используют отдельную БД `max_webapp_unittest`. В проверках доставки MAX API подменяется: реальные пользователи не получают тестовые сообщения. Браузерные проверки подтверждают выбор нужного endpoint и отделение черновиков, а также проверяют форматирование и адаптивную вёрстку.

Для переноса в основной бот нужен успешный ручной прогон всех трёх сценариев, изоляции пользователей, баланса и уточнений. Одного успешного самостоятельного расклада WebApp недостаточно.
