# Проверка чата и WebApp

Три сценария ниже уже работают в рабочем боте. Ручной прогон нового изменения сначала делают на локальном тестовом боте, не на рабочем токене и не через рабочий xTunnel.

Локально: репозиторий `max_bot`, команда `scripts/webapp_local.py max`, база `max_webapp_test`. Запуск и границы: [README-WEBAPP.md](../README-WEBAPP.md).

| Начало | Выбор карт | Ответ и уточнения |
|---|---|---|
| Вопрос в чате | Случайные карты либо названия своих карт в чате | В чате: сначала общая картинка, потом текст |
| Вопрос в чате | «Выбрать карты самой», затем «Выбрать карты для чата» | В чате, в том же порядке |
| Главная приложения | Любой способ выбора и любая схема | Только в приложении |

Вопрос из чата в выборе карт виден, но в самостоятельный черновик не подставляется. Баланс, история и счётчик уточнений общие. Самостоятельный расклад приложения не становится текущим раскладом чата. Для выбора карт под чат сервер проверяет пользователя, вопрос и версию начатого выбора.

## Запуск локальной проверки

Туннель `cloudflared` направляют на `http://127.0.0.1:8091` и прописывают в кабинете тестового бота. Рабочий адрес `01a0ba9c-….tunnel4.com` для локального процесса не используют.

Остановить предыдущий локальный процесс через Ctrl+C и запустить:

```bash
.venv-webapp/bin/python scripts/webapp_local.py max
```

Если база уже слушает `127.0.0.1:55439`, заново её поднимать не нужно. После смены кода закрыть и снова открыть приложение в MAX.

## Прогон

Два разных тестовых аккаунта проверяют изоляцию вопросов, истории и балансов. Одновременные действия одного пользователя проверяют одним аккаунтом на двух устройствах.

1. **Чат полностью.** Новый вопрос, Таро, «Карты покажут сами». Ожидается одна картинка трёх карт и после неё текст. Уточнение относится к этому раскладу. Повторить с «Написать свои карты» и отдельно с Ицзин. Гексаграмма без файла в `static/geks/` не должна выпасть.
2. **Выбор карт в приложении для чата.** Новый вопрос, «Выбрать карты самой», «Выбрать карты для чата», три карты, «Получить ответ в чате». Приложение показывает завершение. В чате сначала картинка, потом текст. Уточнение пишут в чате.
3. **Самостоятельное приложение.** Другой вопрос, все схемы и способы выбора. Ответ и уточнения остаются в приложении, сообщений в чат нет. История открывает сохранённый результат.
4. **Два расклада.** Чат получает расклад A, приложение — расклад B. Уточнение в чате относится к A, уточнение внутри B — к B.
5. **Шаг чата.** Начать ввод вопроса или карт в чате, открыть приложение и вернуться. Незавершённый шаг чата сохраняется.
6. **Устаревший выбор.** Открыть выбор карт для вопроса A. На втором устройстве начать вопрос B. Отправка старого выбора A отклоняется без списания.
7. **Повторы.** Повторная отправка и закрытие приложения во время ожидания дают одну запись и одно списание. Повторное открытие готового ответа баланс не меняет.
8. **Перезапуск.** Во время ожидания перезапустить только тестовый процесс. Запрос завершается после запуска; повторное нажатие второй расклад не создаёт. При ошибке генерации списания нет.
9. **Остальные разделы.** Карта дня, история, избранное, заметки, баланс, обе консультации. Оплату проверяют только ключом ЮKassa с префиксом `test_`. Пустые ключи означают, что оплата выключена, а не что платёж прошёл.

Для каждого пункта записать аккаунт, устройство, время, ожидаемый и фактический результат и изменение баланса.

## Автоматические проверки

```bash
.venv-webapp/bin/python scripts/test_webapp.py
.venv-webapp/bin/python scripts/test_webapp_ui_regressions.py
```

Серверные проверки используют `max_webapp_unittest`. Доставка в MAX в них подменяется, сообщения тестовым пользователям не уходят. Автоматический прогон не заменяет пункты выше на телефоне.
