# Этап 5: запуск RuStore Pay

Код реальных покупок готов. RuStore Console Application ID `2063751721` задан в Android-сборке, но до настройки серверных секретов API возвращает `billing_enabled=false`, а кнопка оплаты не показывается. ЮKassa в эту итерацию не подключается.

## Что реализовано

- Android: RuStore Pay SDK 11.1.0, возврат из банковского приложения по deeplink, передача внутреннего `appUserId`, покупка в один этап и acknowledgement после серверного начисления.
- API: `POST /v1/billing/rustore/verify` независимо проверяет покупку через RuStore Public API.
- БД: уникальные `purchase_id` и `invoice_id` не допускают повторного начисления.
- Callback: `POST /v1/webhook/rustore` расшифровывает AES-256-GCM уведомления, повторно безопасен, отзывает доступ при возврате и обновляет срок подписки.
- Каталог: ЮKassa убрана из доступных способов; консультации остаются видимыми, но без оплаты.

## Сервер

Применить только к `app_bot_db`:

```bash
psql -U app_bot_user -d app_bot_db -h localhost -f app/migrations/006_rustore_billing.sql
```

Добавить в серверный `.env`:

```env
APP_RUSTORE_CONSOLE_APP_ID=2063751721
APP_RUSTORE_KEY_ID=<id ключа>
APP_RUSTORE_PRIVATE_KEY=<приватный ключ Base64>
APP_RUSTORE_CALLBACK_KEY=<AES-ключ callback Base64>
APP_RUSTORE_API_BASE_URL=https://public-api-m.rustore.ru
APP_RUSTORE_SANDBOX=true
```

Хост с суффиксом `-m` использует российскую цепочку сертификатов. На VM нужно установить корневой и промежуточный сертификаты Минцифры по актуальной инструкции RuStore и проверить TLS до `public-api-m.rustore.ru`.

После изменения зависимостей перезапустить `app-api`. Проверка `GET /v1/catalog` под access-токеном должна вернуть `billing_enabled: true`, `payment_methods: ["rustore"]`.

## Sandbox-приёмка

1. Собрать APK с числовым ID консоли и подписью, зарегистрированной в RuStore.
2. Войти в приложение через VK ID или email и запомнить баланс.
3. Купить каждый пакет; проверить ровно одно начисление и повтор `/verify` без второго начисления.
4. Купить `unlimited`; проверить срок в профиле и восстановление после входа на другом устройстве.
5. Закрыть платёжную шторку и оборвать сеть после оплаты; деньги/баланс не должны расходиться, повторная проверка должна восстановить результат.
6. Выполнить sandbox-возврат: неиспользованный остаток снимается, подписка выключается, callback-дубликат ничего не меняет.
7. После полного sandbox-прогона переключить отдельный production-контур на `APP_RUSTORE_SANDBOX=false`; тестовые платежи в production-БД не переносить.

Не коммитить приватный ключ, callback-ключ, `.env` и release keystore.
