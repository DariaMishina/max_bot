# Обычный вход по логину и паролю — 0.8.2 (8)

Реализован для всех пользователей. Модератор использует обычный аккаунт и те же API/экраны, без специальных паролей или обхода проверок. VK ID и email-код сохраняются.

## Поведение

- Логин: 6–32 латинские буквы, цифры, `_`; регистр не важен, внешние пробелы удаляются.
- Пароль: 12–128 символов, включая пробелы; регистр важен. Пароль не обрезается и не нормализуется сервером.
- Регистрация требует подтверждения пароля на экране и сигнала устройства. Сервер транзакционно создаёт аккаунт, идентификатор, баланс и парольную запись.
- Хеш: scrypt N=131072, r=8, p=1, случайная соль 16 байт, результат 32 байта; вычисление вне event loop, не более двух одновременно на процесс. Параметры соответствуют [рекомендации OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
- Лимиты в PostgreSQL: за 15 минут не более 5 регистрационных запросов с одного IP, 60 попыток входа с IP и 10 запросов на один логин для каждого действия. Неудачные попытки учитываются независимо от отката регистрации. Вход с неверным паролем и неизвестным логином возвращает одинаковую ошибку.
- IP берётся из `request.remote`, непроверенные forwarded-заголовки не используются. За reverse proxy это может быть общий адрес: перед публичным выпуском проверить реальные лимиты через ingress и настроить доверенную передачу IP или ограничения на proxy.
- Пробные 3 расклада выдаются через существующие `app_trial_claims`: один раз на идентификатор и сигнал устройства. Это не доказательство личности; смена и логина, и сигнала устройства остаётся ограничением существующей защиты от злоупотреблений.
- Повторный вход открывает тот же аккаунт и не выдаёт подарок. Refresh/logout/удаление работают через общие сессии. Удаление пользователя каскадно удаляет парольный хеш; записи запрета повторного подарка сохраняются.
- Новый логин создаёт отдельный аккаунт. Автоматического объединения с существующим email/VK-аккаунтом нет. Существующие пользователи продолжают входить прежним способом.
- Восстановление/смена забытого пароля и добавление пароля к прежнему аккаунту пока не реализованы. На регистрации показано предупреждение о необходимости сохранить логин и пароль. Привязанный через профиль VK ID остаётся альтернативным входом.

## Развёртывание (не выполнялось при локальной реализации)

1. Сделать резервную копию БД приложения. Выбрать staging `app_bot_db`, не БД бота.
2. Применить `app/migrations/007_password_auth.sql` после миграции 005. Она добавляет таблицы credentials/limits и не меняет существующих пользователей.
3. Развернуть новую версию `app-api`. Действующий workflow останавливает deploy при новых миграциях без подтверждения; после применения запускать с `confirm_migrations_applied=true`.
4. Проверить API и установить новый APK на телефон. Старый сервер не знает новых endpoints; одного обновления APK недостаточно.
5. Проверить регистрацию, выход/повторный вход, сохранение баланса и истории, неверный пароль, VK ID/email и удаление отдельного аккаунта. Убедиться, что секреты отсутствуют в журналах.
6. Создать обычный аккаунт для модератора через «Регистрация», сохранить логин/пароль вне Git и убедиться, что хватает баланса для проверки. Пароль от почты не требуется.
7. Собрать подписанный alpha AAB `0.8.2 (8)` с staging URL, проверить подпись/версию и загрузить в RuStore. Если код 8 уже занят в консоли, увеличить его перед сборкой. Старый AAB `0.8.1 (7)` не обновляется автоматически.

## API

`POST /v1/auth/password/register`: `login`, `password`, `device_signal`.

`POST /v1/auth/password/login`: `login`, `password`. Не требует SMTP или VK.

Оба возвращают стандартные `access_token`, `refresh_token`, `user_id`, баланс и `trial_granted`. Клиент сохраняет только токены, а пароль удаляет из состояния формы после попытки входа.

## Проверки

`venv/bin/python -m unittest discover -s tests -v` — unit-тесты.

Для настоящих транзакций запустить временный PostgreSQL и задать `PASSWORD_TEST_DSN`, затем ту же команду. `tests/test_password_auth.py` создаёт отдельную случайную схему для каждого теста и удаляет только эту схему. Не использовать production DSN.

Проверяются HTTP-регистрация/вход/refresh/удаление, конкурирующая регистрация, отсутствие повторного подарка, неверные пароли/неизвестные логины, сохранение и истечение лимитов, а также сохранение счётчика неверных email-кодов.

`bash scripts/check_android.sh` — APK, unit-тесты модулей и lint.
