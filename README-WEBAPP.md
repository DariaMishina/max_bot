# WebApp «Сфера Таро» — локальная тестовая ветка

Ветка: `feature/max-webapp`. Рабочий сервер, production-бот и Android не используются.
Исходный диагностический проект сохранён в `main`; его `probe.py`, `.env`, README и зависимости не менялись.

## Что работает

- Сиреневый интерфейс с мотивами «Орбиты» и «Лунного атласа»: главная, расклад, история, профиль.
- Три способа Таро: выбор 3 из 9, случайные карты, поиск своих карт. Несколько схем с соответствующими позициями в инструкции LLM.
- Ицзин, сохранённое толкование, уточнения с общими лимитами для чата и приложения.
- История, поиск, фильтры, избранное и личные заметки.
- Карта дня, сохранённая по московской дате и общая с чатом.
- Баланс, витрина пакетов, консультации и форма обратной связи.
- Проверка подписи MAX, ограничение тестировщиков по ID, защита повторных запросов.
- Операции в PostgreSQL: результат и списание одной транзакцией, восстановление очереди после остановки, доставка сообщения в MAX после сохранения результата.
- Тестовые платежи ЮKassa: сохранённый ключ повторного запроса, проверка суммы/пользователя/пакета, однократное начисление. По умолчанию оплата выключена.

## Локальные ресурсы

| Ресурс | Адрес / путь |
|---|---|
| WebApp и API | `http://127.0.0.1:8091` |
| PostgreSQL | `127.0.0.1:55439` |
| База для ручной проверки | `max_webapp_test` |
| База автоматических проверок | `max_webapp_unittest` |
| Пользователь локального кластера | `webapp_local` |
| Данные кластера | `.local-webapp/postgres/` |
| Окружение WebApp | `.venv-webapp/` |
| Настройки WebApp | `.env.webapp` |
| Токен отдельного бота | `BOT_TOKEN_TEST` в `.env` |

Кластер создаётся отдельно и слушает только loopback. Он не использует существующие PostgreSQL-сервисы компьютера. Запускатель фиксирует локальные адрес, порт и имена БД; параметры рабочей БД из других проектов не читаются. Локальный кластер использует доверенную аутентификацию для работы на этом компьютере.

Для совместимости с существующим диагностическим проектом запускатель также понимает `MAX_TEST_BOT_TOKEN`, если `BOT_TOKEN_TEST` отсутствует. Значение `BOT_TOKEN` никогда не используется как запасной вариант.

## Запуск демонстрации

Из папки `max_bot`, ветка `feature/max-webapp`:

```bash
python3 -m venv .venv-webapp
.venv-webapp/bin/python -m pip install -r requirements-webapp.txt
.venv-webapp/bin/python scripts/webapp_local.py db
.venv-webapp/bin/python scripts/webapp_local.py demo
```

Открыть **http://127.0.0.1:8091**. Первые две команды нужны только при первоначальной установке.

Деморежим использует локальную БД и явно помеченные демонстрационные ответы; он не отправляет сообщения в MAX и не вызывает DeepSeek. Демо-пользователь имеет ID `900000001`. Это не эмуляция настоящего входа MAX: подлинный вход проверяется отдельно.

Не публикуйте деморежим через туннель. Для телефона используйте режим `max`, описанный ниже.

## Проверка в MAX с локальным backend

1. Заполнить `.env.webapp` по `.env.webapp.example`:
   - `API_KEY` — ключ DeepSeek для реального толкования;
   - `WEBAPP_ALLOWED_IDS` — ваши MAX user ID, через запятую;
   - `PUBLIC_BASE_URL` — HTTPS-адрес туннеля к локальному порту 8091;
   - ключи ЮKassa оставить пустыми до отдельной проверки тестового магазина.
2. Убедиться, что в `.env` есть отдельный тестовый токен.
3. Остановить демосервер (`Ctrl+C`) и диагностический `probe.py`, если он использует этого же бота.
4. Убедиться, что у тестового бота не осталось webhook-подписки диагностического проекта: нельзя одновременно использовать её и long polling. Этот проект не удаляет подписки автоматически.
5. Запустить:

```bash
.venv-webapp/bin/python scripts/webapp_local.py db
.venv-webapp/bin/python scripts/webapp_local.py max
```

6. В другом терминале при необходимости запустить HTTPS-туннель только к локальному backend:

```bash
cloudflared tunnel --url http://127.0.0.1:8091
```

7. Полученный HTTPS-адрес указать в `PUBLIC_BASE_URL` и в настройках мини-приложения **тестового** бота. После изменения `.env.webapp` перезапустить режим `max`.
8. Открыть приложение из MAX. В браузере по тому же публичному адресу без подписанных данных запуск будет отклонён.

Туннель лишь обеспечивает доступ телефона к компьютеру — код и БД остаются локально. Его запуск и привязка URL к боту в рамках текущей реализации не выполнялись. Временный URL меняется при новом запуске: обновите настройки, не используйте адрес рабочего xTunnel.

Режим `api` запускает только HTTP-часть с настоящей проверкой MAX; основная проверка чата и приложения выполняется в режиме `max`.

Автоматические рассылки, аналитика Метрики и отправка обратной связи другим людям выключены. Отзывы и события воронки сохраняются только локально; тексты вопросов не записываются в таблицу продуктовых событий.

## Тестовая оплата

В `.env.webapp` допускается только ключ ЮKassa с префиксом `test_`. Реальные платежи запускатель блокирует. Контакт таролога задаётся отдельно и показывается после подтверждённой консультации.

В этой ветке статус платежа проверяется обращением к ЮKassa с сервера по кнопке «Проверить последний платёж». Внешний callback production не используется, `/webhook/yookassa` не опубликован. Если локальный сервер остановлен, проверить начисление можно после его запуска. Перед переносом функциональности в рабочий проект нужно отдельно проверить интеграцию с действующим callback; здесь серверный деплой не предусмотрен.

## Автоматические проверки

```bash
.venv-webapp/bin/python scripts/test_webapp.py
```

Запускатель создаёт `max_webapp_unittest` в том же локальном кластере. Проверки подписи, API, платежей и транзакций не затрагивают базу ручного демо. Ошибки в журнале тестов сбоя LLM и исчерпания лимита ожидаемы — тест проверяет отсутствие списания.

Для браузерной проверки оставить работающий `demo`:

```bash
.venv-webapp/bin/python -m pip install -r requirements-webapp-dev.txt
.venv-webapp/bin/python -m playwright install chromium
.venv-webapp/bin/python scripts/test_webapp_browser.py
.venv-webapp/bin/python scripts/test_webapp_browser_edges.py
```

Браузерные проверки создают записи демо-пользователя и восстанавливают его тестовый баланс. Они проверяют интерфейс, три режима карт, Ицзин, потерю ответа/повтор без второго списания, заметки и восстановление черновика. Скриншоты: `.local-webapp/screenshots/`.

Результат проверки 30.10.2026: 35 проверок нового API/сервиса/подписи и платежей, 15 проверок вопросов/маршрутизации/health, 5 исходных проверок диагностического проекта — успешно. Два браузерных сценария прошли; адаптивность проверена на 320, 390 и 412 px, включая увеличенный шрифт.

## Работа с ветками

Код функций хранится в Git, а локальные базы, секреты и окружения остаются вне Git. Для них дополнительно настроен `.git/info/exclude`, действующий во всех ветках.

Перед переключением:

1. Остановить WebApp/бота в его терминале (`Ctrl+C`).
2. При необходимости остановить локальный кластер:

```bash
.venv-webapp/bin/python scripts/webapp_local.py stop-db
```

3. Проверить `git status`. Сохранить изменения локальным коммитом или stash, затем переключиться:

```bash
git switch main
# Возврат к WebApp:
git switch feature/max-webapp
```

Не запускайте два процесса с одним тестовым токеном одновременно. Ветки разделяют код; настройки мини-приложения и webhook-подписки в MAX принадлежат самому боту и не переключаются вместе с Git.

## Что ещё требует внешней проверки

- Настоящий вход в MAX WebView, кнопка открытия и возвраты с оплаты на телефоне.
- Ответы DeepSeek с заполненным ключом, доставка в чат и совместный сценарий чата/WebApp.
- Тестовый магазин ЮKassa с настоящими тестовыми ключами. Сейчас проверены имитированные ответы провайдера.
- Ручная оценка анимаций, клавиатуры и экранного диктора в MAX.
- Настройка времени напоминаний отложена: действующий backend поддерживает подписку на карту дня, а локальные фоновые рассылки намеренно отключены.
