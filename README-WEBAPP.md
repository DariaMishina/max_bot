# WebApp «Сфера Таро»

Мини-приложение бота MAX в этом репозитории. Пользователь, баланс, история, уточнения и оплата общие с чатом. Это не Android-приложение и не его веб-версия: у Android свои аккаунт, база и оплата.

Код: `webapp/`, `main/webapp_*.py`, маршруты в `webhook_server.py`. Схема: `migrations/20261031_max_webapp.sql` в `max_bot_db`. На базы Android её не применяют.

## Рабочий адрес

В кабинете бота `@id132608020863_bot` кнопка мини-приложения имеет тип «Открыть» и адрес:

`https://01a0ba9c-b091-79dc-9a97-07e3b1eba847.tunnel4.com`

Страница, `/assets/` и `/api/webapp/` открываются с этого же адреса. Интерфейс ходит в относительные пути, поэтому GitHub Pages мини-приложением не является. Workflow `.github/workflows/pages.yml` по-прежнему публикует каталог `webapp/`, но в кабинете MAX этот адрес не используется.

Маршруты nginx и порты: [docs/WEBAPP-BACKEND-FIX.md](docs/WEBAPP-BACKEND-FIX.md).

## Три сценария

| Начало | Выбор карт | Куда приходит ответ |
|---|---|---|
| Вопрос в чате | Случайные карты или свои названия в чате | В чат |
| Вопрос в чате | «Выбрать карты самой», в приложении «Выбрать карты для чата» | В чат |
| Вопрос в приложении | Любой способ и любая схема | Только в приложении |

В чат сначала уходит общая картинка карт, затем текст толкования ответом на вопрос. Расклад, начатый в приложении, в чат не отправляется.

Вопрос из чата показывается в выборе карт и не подставляется в самостоятельный черновик. Уточнение в чате относится к чатовому раскладу, уточнение внутри результата — к этому результату. Повторное открытие готового ответа новое гадание не создаёт. Устаревшая вкладка выбора карт для уже сменённого вопроса отклоняется без списания.

Ручная проверка этих сценариев: [docs/TEST_CHAT_AND_WEBAPP.md](docs/TEST_CHAT_AND_WEBAPP.md).

## Что есть в приложении

Нижняя навигация: главная, расклад, история, профиль.

- Главная: шесть тем (отношения, работа и карьера, финансы, перемены, мой выбор, о себе), карта дня, консультация, баланс. Тема подставляет редактируемый вопрос. Схему расклада меняет только явный выбор.
- Расклад: выбрать карты, случайные карты, поиск своих карт. Ответ хранит позиции и общее толкование.
- Ицзин берёт только гексаграммы, для которых есть файл в `static/geks/`.
- История, избранное, фильтры, личная заметка. Активный запрос можно снова открыть на экране ожидания.
- Экран ожидания показывает принятый вопрос и прошедшее время, без выдуманных процентов генерации.
- Профиль, пакеты из серверного каталога, базовая и подробная консультации. Цены задаёт сервер.

Картинки карт в интерфейсе берутся из `webapp/card-data.js`. Картинки в чате и гексаграммы — из `static/`.

## Вход и оплата

Отдельной регистрации нет. Сервер проверяет подпись запуска MAX в заголовке `X-Max-Init-Data` и сам определяет пользователя. Список `WEBAPP_ALLOWED_IDS` ограничивает вход только при `WEBAPP_LOCAL=true`. В рабочем боте эта переменная не задаётся.

Оплата идёт тем же магазином ЮKassa, что и в чате. Зачисление делает webhook `https://max-bot-awtw.onrender.com/webhook/yookassa`. Открытая страница оплаты баланс не меняет. `SERVICE_URL` остаётся адресом Render и не заменяется адресом xTunnel. Чек-лист: [docs/YOOKASSA_CHECKLIST.md](docs/YOOKASSA_CHECKLIST.md).

Старые маршруты `/api/webapp/cards` и `/api/webapp/pending-question` ещё отвечают прежнему выбору карт и подпись initData не проверяют. Текущий интерфейс их не вызывает.

## Локальная проверка

Локальный запуск не читает рабочий `BOT_TOKEN`, не использует боевые ключи ЮKassa и не открывается через рабочий xTunnel. База — отдельный PostgreSQL на этом компьютере.

| Ресурс | Адрес |
|---|---|
| Приложение и API | `http://127.0.0.1:8091` |
| PostgreSQL | `127.0.0.1:55439` |
| Ручная база | `max_webapp_test` |
| База автоматических проверок | `max_webapp_unittest` |
| Пользователь кластера | `webapp_local` |
| Данные | `.local-webapp/postgres/` |
| Окружение | `.venv-webapp/` |
| Настройки | `.env.webapp` по `.env.webapp.example` |

Токен тестового бота — `BOT_TOKEN_TEST` в `.env.webapp` или в `.env`. Если его нет, запускатель понимает `MAX_TEST_BOT_TOKEN`. Значение `BOT_TOKEN` запасным вариантом не служит. Совпадение тестового токена с рабочим запускатель отклоняет.

Демонстрация без MAX и без DeepSeek:

```bash
python3 -m venv .venv-webapp
.venv-webapp/bin/python -m pip install -r requirements-webapp.txt
.venv-webapp/bin/python scripts/webapp_local.py db
.venv-webapp/bin/python scripts/webapp_local.py demo
```

Открыть `http://127.0.0.1:8091`. Демо-пользователь имеет ID `900000001`. Демонстрацию через туннель не публикуют: она принимает только локальное подключение.

Проверка в тестовом боте MAX:

1. В `.env.webapp` заполнить `API_KEY` (DeepSeek), `WEBAPP_ALLOWED_IDS` и `PUBLIC_BASE_URL`. Ключ ЮKassa, если он нужен, только с префиксом `test_`. Пустые ключи оставляют оплату выключенной.
2. Остановить демо (`Ctrl+C`). Не держать второй процесс с тем же тестовым токеном.
3. Запустить `.venv-webapp/bin/python scripts/webapp_local.py max`.
4. Для телефона поднять туннель только к локальному порту: `cloudflared tunnel --url http://127.0.0.1:8091`. Полученный адрес записать в `PUBLIC_BASE_URL` и в кабинет тестового бота, затем перезапустить режим `max`. Рабочий адрес `tunnel4.com` для этого не использовать.
5. Открыть приложение из MAX. Тот же публичный адрес в обычном браузере без подписи запуска отклоняется.

Режим `api` поднимает только HTTP. Рассылки, Метрика и пересылка отзывов в этом режиме выключены.

Автоматические проверки:

```bash
.venv-webapp/bin/python scripts/test_webapp.py
.venv-webapp/bin/python scripts/test_webapp_ui_regressions.py
```

Браузерные сценарии требуют запущенный `demo`, пакет `requirements-webapp-dev.txt` и Playwright. Они пишут в базу демо-пользователя. Скриншоты: `.local-webapp/screenshots/`.

Остановить локальный кластер: `.venv-webapp/bin/python scripts/webapp_local.py stop-db`.
